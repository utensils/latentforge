# API Overview

LatentForge is a small Python package with a single-purpose agent loop and a collection of MCP tools. This section documents everything the agent can call.

## Tools

The [**Tools Reference**](/api/tools) covers all 22 MCP tools that make up the agent's dataset-building capability. Tools are auto-generated from [`src/latentforge/tools.py`](https://github.com/utensils/latentforge/blob/main/src/latentforge/tools.py) — whatever you see on that page matches the source exactly.

Tools are grouped by category:

| Category | Tools | What it does |
| --- | --- | --- |
| [Config Management](/api/tools#config-management) | 4 | Create, read, update, and list dataset YAML configs. |
| [Search & Download](/api/tools#search-download) | 4 | Query Bing and Wikimedia; download URL lists and gallery-dl-compatible sites. |
| [Dataset Browsing](/api/tools#dataset-browsing) | 2 | List images with metadata; inspect a single image. |
| [Dataset Organization](/api/tools#dataset-organization) | 2 | Move images between categories; auto-sort by filename prefix. |
| [Quality & Curation](/api/tools#quality-curation) | 5 | Resolution stats, perceptual-hash dedup, resize, captions, screenshot detection. |
| [Cropping & Face Detection](/api/tools#cropping-face-detection) | 4 | Center/smart crops, face detection, portrait crops. |
| [Export](/api/tools#export) | 1 | Export to ai-toolkit format with generated training config. |

## Built-in tools

In addition to the 22 MCP tools, the agent is given three built-in SDK tools:

- **`Read`** — reads files. Has vision, so it can examine images directly.
- **`Write`** — writes files (under `permission_mode="acceptEdits"`, so no prompts).
- **`Bash`** — shell access for anything the MCP tools don't cover.

These are what let the agent look at an image and say "that's a watermark, let me move it to `rejected/`" without a dedicated tool for vision inspection.

## Python modules

The package itself is tiny — three modules under `src/latentforge/`:

| Module | Purpose |
| --- | --- |
| [`agent`](https://github.com/utensils/latentforge/blob/main/src/latentforge/agent.py) | CLI entry, REPL, session state, slash commands, compaction |
| [`tools`](https://github.com/utensils/latentforge/blob/main/src/latentforge/tools.py) | All 22 `@tool` functions |
| [`prompts`](https://github.com/utensils/latentforge/blob/main/src/latentforge/prompts.py) | System prompt builder |

See [Architecture](/guide/architecture) for how they fit together.

## Regenerating the tools reference

The tools reference is generated by a small Python script that parses `tools.py` with `ast`:

```bash
pnpm run docs:gen
# or
python scripts/gen_api_docs.py
```

It's idempotent — running it twice produces the same file. The output is committed, so the VitePress build doesn't need Python at build time.
